# 叶7 · 可靠性语义

权威：Google AIP-151（长时操作）、AWS Builders' Library（重试/幂等模式）、Google SRE Book（重试风暴）。

## 判据

1. **超时是契约的一部分**：每个操作必须声明服务端超时与客户端建议超时；
   无超时的同步端点＝连接池耗尽风险（blocking）。gRPC 用 `deadline`，HTTP 用服务端超时 + 客户端约定。
2. **取消传播**：客户端断开/取消必须能中止服务端工作（尤其长任务），
   否则资源继续被占用（advisory→blocking 视成本）。
3. **重试三条件**：只有「可重试错误 + 幂等操作 + 有退避」同时成立才允许自动重试；
   缺任一条即把重试语义写清并禁止客户端盲目重试（转叶4 错误模型）。
4. **退避必须带抖动**：固定间隔重试造成同步风暴（SRE 明确反模式）；
   契约应给出建议退避（指数 + jitter + 上限次数）。
5. **熔断与降级**：跨服务依赖须声明失败时的降级形态（返回缓存/部分数据/明确 503），
   「静默返回空列表」＝数据正确性缺陷（blocking）。
6. **幂等键设计**：非幂等写操作接受客户端生成的 `Idempotency-Key`，
   服务端保存窗口须声明（多久内重放安全）；键复用返回首次结果而非重复执行。
7. **投递语义声明**：消息/事件必须写明 at-most-once / at-least-once / exactly-once（效果等价）；
   未声明＝消费方无法决定是否去重（blocking）。真实 exactly-once 跨系统不可达，须给去重键方案。
8. **顺序保证边界**：声明是否保证同键有序（partition key / message group）；
   无序场景须让消费方按事件时间或版本号自行排序。
9. **长时操作模式**：超过秒级的操作走 202 + 操作资源（`/operations/{id}`）或回调，
   不得让客户端挂长连接等待（AIP-151）。
10. **背压与限流协同**：429/RESOURCE_EXHAUSTED 必须给恢复时间，且与重试退避共用同一预算说明。

## 取证

`scripts/error_model_probe.py`（可重试类别是否可推）、`scripts/compat_probe.py`（新增超时/重试字段是否破坏）。
