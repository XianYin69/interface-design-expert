# 专家判断

## 目的

把判据与证据合成结论；每条判断落逻辑链（证据→结论→取舍→边界）。

## 动作

1. 逐条判断按四段式写：
   - **证据**：探针命中或规范小节（含出处键 + 命令原文）。
   - **结论**：`blocking` / `advisory` / `info` 三档，只有 blocking 能阻断发布。
   - **取舍**：为什么不是另一选项（如 cursor 而非 offset 的量化理由）。
   - **边界**：结论在什么条件下反转（客户端数量、是否公开、是否有网关兜底）。
2. 判据优先级冲突仲裁（见 [评审约束](../../../resistance/评审约束/评审约束.md)）：
   安全与数据正确性 > 兼容性（是否破坏既有客户端）> 规范一致性 > 人体工学 > 风格口味。
3. 兼容性判定必须给**影响面**：哪些客户端会失败、失败形态（400/500/静默错值）、
   回滚窗口；判不了就标 `unknown`，不得默认「应该没问题」。
4. 用 `scripts/advice_compose.py --topic <叶> --verdict tmp/verdict.json` 合成结构化结论。
5. 反直觉结论（如「加字段也可能破坏」）必须跑 `compat_probe.py` 复现或引规范原文。

## 输出

`结论集`：四段式判断列表 + 分档统计 + 仲裁记录。

## 降级

证据与判据矛盾 → 不合并，两条都保留并标 `conflict`，回调用方补信息，不得强行给单一结论。
