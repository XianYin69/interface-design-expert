# 流程（Process）

interface-design-expert 的执行流程细则。每个步骤独立成文件夹，文件夹名＝流程名。

## 主路径（被调用时的接口设计评审）

```
[初始化/](初始化/初始化.md) → [问题解析/](问题解析/问题解析.md) → [领域定位/](领域定位/领域定位.md) →
[知识检索/](知识检索/知识检索.md) → [取证探查/](取证探查/取证探查.md) → [专家判断/](专家判断/专家判断.md) →
[评审清单/](评审清单/评审清单.md) → [契约建议/](契约建议/契约建议.md) → [输出交付/](输出交付/输出交付.md) →
[收尾/](收尾/收尾.md) → 完成
```

## 修改路径（本技能自身演进）

```
[初始化/](初始化/初始化.md) → [修改流程/](修改流程/修改流程.md) → 完成项目修改
```

## 横切节点

[浏览器学习](浏览器学习/浏览器学习.md)：任一步骤遇到不明确的规范条款、字段语义、工具行为，
强制先派 `file_ops` 检索学习并给出出处，再回原节点继续；不得凭记忆作答。

## 全局机制

各节点均受 [resistance/](../../resistance/resistance.md) 五大机制约束：
[垃圾回收机制](../../resistance/垃圾回收机制/垃圾回收机制.md)、
[上下文压缩机制](../../resistance/上下文压缩机制/上下文压缩机制.md)、
[逻辑链机制](../../resistance/逻辑链机制/逻辑链机制.md)、
[过程链存取](../../resistance/过程链存取/过程链存取.md)、
[惩罚机制](../../resistance/惩罚机制/惩罚机制.md)。

## 步骤语义

| 步骤 | 输入 | 产出 | 主要脚本 |
|---|---|---|---|
| 初始化 | 调用方诉求 | 会话基线 | knowledge_index |
| 问题解析 | 契约文本/路径 | 结构化问题 | classify_topic |
| 领域定位 | 结构化问题 | 多标签叶集合 | classify_topic |
| 知识检索 | 叶 id | 判据 + 清单 | knowledge_index |
| 取证探查 | 契约文件 | 可复现证据 | contract_lint · compat_probe · naming_probe · error_model_probe · codegen_probe |
| 专家判断 | 证据 + 判据 | 结论/取舍/边界 | advice_compose |
| 评审清单 | 结论 | BLOCK 判定表 | review_checklist |
| 契约建议 | BLOCK 表 | 演进与迁移方案 | compat_probe |
| 输出交付 | 全部 | 固定格式报告 | advice_compose |
| 收尾 | 报告 | 存档 + git 提交 | check_links |
