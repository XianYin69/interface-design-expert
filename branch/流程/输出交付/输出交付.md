# 输出交付

## 目的

以固定格式交付，让调用方能直接执行；缺「边界」或「未覆盖」即判不合格。

## 格式

```
结论：blocking N · advisory M · info K（一句话主判断）
阻塞项：（每条）问题 → 证据（命令/规范小节） → 最小修复
建议：（按优先级）形状 → 理由（出处键） → 迁移窗口
取证：探针命令原文 + 工具版本（未取证项标「无取证」）
边界：结论在什么条件下反转（客户端数量/是否公开/有无网关/协议族差异）
未覆盖：没查的叶、没跑的探针、缺少的输入
```

## 规则

1. 数字与版本只来自 `scripts/` 输出或用户原文；推测值必须标「假设」。
2. 每条 blocking 必须可复现：给出命令或规范小节，调用方一跑就能验证。
3. 不得把命名口味写成 blocking；不得用「建议遵循最佳实践」替代具体形状。
4. 转派项单列一行：问题 → 目标技能（`concurrency-design` / `database-management` /
   `ui-design` / `performance` 类），不得沉默吞掉。
5. 长度：默认 ≤ 60 行；调用方要「三句话」时压到三句但保留边界一句。

## 输出

交付文本 + `tmp/verdict.json`（结构化结论，供 `advice_compose.py` 与调用方链存档）。
