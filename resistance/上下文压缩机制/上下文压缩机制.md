# 上下文压缩机制

## 目的

接口契约动辄数百行；本技能不得把整份契约塞进上下文，只带**定位后的窗口**。

## 规则

1. 读契约先定位再取窗：`grep` 找操作/字段行号 → 按 offset 续读必要片段（≤ 60 行/次）。
2. 探针输出只保留 `findings[]` 与命令原文，原始 JSON 留 `tmp/` 不复述。
3. 多轮评审同一契约时，后续轮次只带**差异片段**（`compat_probe` 输出）而非全文。
4. 交付文本压缩优先级：删证据原文（留命令）→ 删 advisory 明细（留计数）→
   合并同类阻塞项；**边界与未覆盖两段永不压缩**。
5. 判据条目按叶取用，不整树载入；跨叶合成时才取第二叶。

## 禁止

- 禁止把整份 OpenAPI/proto 文件贴进回复。
- 禁止用「上文已述」替代必要证据（调用方看不到 tmp）。

## 违反后果

上下文膨胀 → 关键判据被挤出、结论与证据错位，评审结果不可复现。
