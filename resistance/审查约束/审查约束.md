# 审查约束

## 取证可追溯

1. 每条 blocking 结论必须附**可复现证据**：探针命令原文，或规范小节引用（含出处键与确证日期）。
2. 探针输出落工作区 `tmp/`，交付里只引结论与命令；缓存不得写入 skill 目录。
3. 外部工具（spectral/buf/oasdiff/protoc）在位时以其输出为准并记版本；
   内置探针结果标 `fallback`。两者冲突必须复核，不得各说各话。
4. 解析失败必须显式标 `parse-skipped`，禁止把「没解析出来」当「通过」。

## 九项整体审查标准（本技能自身发布前）

1. SKILL.md 含 YAML frontmatter，且提示词一句话精简。
2. 悬空链接为 0（`python scripts/check_links.py --root . --strict-url`）。
3. 所有 .md ≤ 50 行；脚本无裸 except、无 print 调试残留、无 >100 字符长行。
4. 九叶知识树三件套齐备：判据 + 权威出处 + 取证脚本，且 json/knowledge/checklists 一一对应。
5. `deps.json` 每条含 `source_url` 原始链接且经确证（`lint-deps.py` 通过）。
6. `planned_tasks/` 存在且 schema 字段名与 SMS 读取端一致；技能自身不执行计划任务。
7. `resistance/` 约束齐备且未被删减。
8. `agent/` 四格式提示词存在且与 SKILL.md 一致。
9. git 历史走功能分支→dev→main，未确认不推送。

## 失败处理

任一项不过 → 记中断（`process_chain.py interrupt`），修复后 `resume` 返回原节点；
重试达 10 次触发 [惩罚机制](../惩罚机制/惩罚机制.md)。
