# 惩罚机制

## 目的

防止在同一错误上无限重试；达阈值即熔断，强制回退或求助调用方。

## 规则

1. 重试计数按**同类错误**累计（同节点 + 同失败签名），阈值 **10 次**即熔断。
2. 每次重试前必须做根因分析并改变做法（换参数/换探针/降级为静态评审/换叶），
   禁止未分析就原样重试。
3. 熔断后动作二选一：
   - **回退**：撤销本步改动（git 回到功能分支上一个可用提交），交回调用方；
   - **求助**：向调用方列出缺失项、已试做法、失败签名，请求拍板。
4. 熔断事件写入 error 链（含签名、已试次数、最后一次输出），供后续会话 `chain recall`。
5. 惩罚只作用于**流程推进**，不得用来绕过红线（例如靠反复重试让 check_links 放行）。

## 禁止

- 禁止伪造通过（跳过校验、手改校验输出）。
- 禁止把熔断当作「任务完成」上报。
- 禁止用无限重试消耗调用方时间而不报告无进展。

## 违反后果

绕过熔断 → 缺陷进入发布分支；伪造通过 → 后续所有评审基于坏数据，不可追溯。
