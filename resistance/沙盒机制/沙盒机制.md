# 沙盒机制

## 目的

未指定目标工作目录时，本技能在固定路径沙盒内作业，避免把过程产物写进调用方或技能目录。

## 规则

1. 沙盒根＝工作区 `tmp/`（`SMS_TMP`）；技能包本体只在收尾经 [update 接口](../../update/update.md) 释放。
2. 评审调用方的契约文件时**只读**：需要生成中间产物（mock、桩、迁移脚本草稿）一律落沙盒。
3. 沙盒内文件命名带会话标识，便于回收；不得假设沙盒路径跨会话存在。
4. 收尾时询问目标路径，交付复制后删除沙盒（垃圾回收约束的例外路径同样不得留残骸）。
5. 沙盒内不得存放真实凭据、生产主机名、用户数据样本——契约示例一律用 `example.com` 与占位 ID。

## 降级

沙盒不可写 → 结论只以文本交付，不落中间文件，并在「未覆盖」段声明未生成 mock/桩。

## 违反后果

过程产物写进技能目录 → 包体污染、缓存泄露内部路径；沙盒残留 → 下次会话误用旧证据。
