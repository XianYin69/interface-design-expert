# 输出约束

## 必须

1. 交付含六段：结论 / 阻塞项 / 建议 / 取证 / **边界** / **未覆盖**（后两段缺项即判不合格）。
2. 每条阻塞项给「最小修复」——改哪个字段、哪一行、加什么头，可直接落地。
3. 每条建议给「形状 + 理由（出处键）+ 迁移窗口」三段。
4. 数字、版本、差异计数只来自脚本输出或用户原文；推测值必须标「假设」。
5. 转派项单列：问题 → 目标技能，不得沉默吞掉。
6. 默认 ≤ 60 行；调用方要短结论时压缩，但「边界」一句不得删。

## 禁止

- 禁止「建议遵循最佳实践」「参考官方文档」这类无具体形状的输出。
- 禁止把命名口味写成阻塞项；禁止用「应该没问题」替代兼容性影响面。
- 禁止输出真实密钥、真实主机名、可猜测的内部 ID 示例。
- 禁止在未取证时写「已验证」「已确认兼容」。
- 禁止把未覆盖的叶伪装成已查（`n-a` 必须写理由）。

## 格式一致性

- 同一契约多轮评审时，条目编号与命名保持稳定，便于 diff。
- 结构化产物 `tmp/verdict.json` 字段：`topic`/`findings[]`/`blocking`/`advisory`/
  `evidence`/`boundary`/`uncovered`（由 `advice_compose.py` 生成）。
