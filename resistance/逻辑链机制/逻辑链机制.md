# 逻辑链机制

## 目的

每条专家判断都要留下「为什么这么判」的可追溯路径，避免同契约前后不一致。

## 记录格式

一条判断四元组：`证据 → 结论 → 取舍 → 边界`。

- 证据：探针命中（含命令原文）或规范小节（含出处键 + 确证日期）。
- 结论：`blocking` / `advisory` / `info`。
- 取舍：为什么不是另一个选项（例：cursor 而非 offset 的量化理由）。
- 边界：结论在什么条件下反转（客户端数量、是否公开、有无网关兜底、协议族差异）。

## 规则

1. 决策岔路（版本机制选型、错误信封选型、分页策略、破坏性判定）**必须**先铺正反双链自辩
   （`logic_chain.py debate`），再定档。
2. 跨叶冲突的仲裁结果必须入链（见 [评审约束](../评审约束/评审约束.md)）。
3. 判据修正（新确证的条款、工具行为差异）入 knowledge 链，供下次 `chain recall` 命中。
4. 链写入用英文精简语句；面向用户的交付文本用调用方语言。
5. 缓存与链存档落用户缓存目录，**不写 skill 目录**。

## 禁止

- 禁止只记结论不记取舍（后续无法判断是否仍适用）。
- 禁止把未取证的推测写入 logic 链当作既往判据复用。
